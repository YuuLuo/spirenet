# 训练说明

[English](TRAINING.md)

本文说明已发布模型是如何训练出来的：系统结构、每个模型的来历，以及最终训练阶段的设置。训练配置本身在
`py/configs/runs/` 中。

## 系统

```
           ┌──────────────── actor 进程（16–32 个）─────────────────┐
 SpireHost │ 50–60 个宿主进程 ── 帧 ──► tokenizer ──► 批量 GPU 推理  │
 (C#)      │      ▲                                    （EMA 权重）  │
           │      └──────────── 动作 ◄──────────────────────────────┘
           └─────────────── 片段（256 步）──► 共享内存环形缓冲
                                                         │
                                         学习器（PPO，1–4 张 GPU）──► 权重 ──► actor
                                                         ▲
                              ExIt 搜索老师进程 ──► 标签分片
```

- **宿主。** 一个 SpireHost 进程一次打一局，通过 stdio 以二进制帧响应 RESET / STEP 请求。
  `actor.reset_flags = 795` 决定帧里包含什么：`AUTO_SINGLE`（只有一个合法动作时自动执行）、`MAP_IN_COMBAT`、
  `UPGRADE_PREVIEWS`、`TARGET_PREVIEWS`、`FORECAST` 和 `CALC`。`HIDDEN`（抽牌顺序）只用于特权 critic 实验，
  宿主不带 `--training-hidden` 启动时会拒绝它；已发布的模型都没有使用。
- **actor。** 每个 actor 进程带 50–60 个宿主，把它们的帧 tokenize 后，用 EMA 权重做 CUDA graph、bf16 的批量推理。
  在战略性决策上把探索混入行为策略（`ppo.exploration_by_kind`：1 地图、5 选牌奖励、6 事件、7 商店、8 营火），
  学习器对此做精确修正。
- **学习器。** PPO，每次迭代 77,824 个样本、跑 1 个 epoch，minibatch 8,192，bf16 autocast、`torch.compile`
  和 CUDA graph。`learner.replica_device` 增加数据并行副本（4M 线一个，FOOL 19M 线三个）。超过 `max_staleness`
  次更新的旧样本会被丢弃。策略已经很确定（`p > confident_tau`）的决策按 `confident_keep` 抽样保留，
  `confident_exempt_kinds` 中的战略性决策除外。
- **吞吐。** 4× RTX 5090（2 张学习 + 2 张推理，约 180 个 CPU 核）：4M 网络每秒 5.5–7 万样本，19M 网络约 3.2 万。
  19M 用 4 张学习 + 4 张推理时约为 1.7 倍。

## 目标函数

- 每局奖励：每层 +0.01，每个精英 +0.02，每个 Boss +0.1，胜利 +1，死亡 −0.1，外加血量项（`hp_coef` 0.1）。
  奖励按每个决策 0.9998 折扣，GAE 中 γ = 1。
- GAE 的 λ = 0.99，战斗内与战斗外决策分开计算（`gae.macro_micro`），并跨片段边界拼接。
- 共享主干上的辅助头：胜率（`aux_win`）、到达层数和损失血量（`aux_floors`、`aux_hp`）。
- 熵奖励在战略性决策上用更大的系数（`ent_coef_by_kind`），另有按 KL 调节学习率的刹车（`kl_lr_target`）和 KL 硬上限（`target_kl`）。

## 已发布训练线用到的方法

- **进阶课程**（`py/scripts/solo_curriculum.py`）：每 20 分钟，把近期至少 200 局、采样胜率至少 15% 的最高进阶记为 a\*；
  之后的对局 30% 在 a\*+1，20% 在 a\*+2，20% 在 a\*，10% 在 a\*−1，10% 在 A10，其余 10% 分给更低的进阶。
  最终的 A10 训练线只打 A10。
- **kickstart 蒸馏**（`ppo.kickstart`、`spire/kickstart.py`）：把训练好的 4M 老师蒸馏进随机初始化的 19M 学生。
  先由老师出牌、学生模仿老师的策略和价值（phase 0），再由学生出牌、老师项逐步撤掉（phase 1）。静默的 19M 网络
  用约 2 亿样本达到了 4M 老师的水平。
- **ExIt**（`spire/exit_teacher.py`、`spire/exit_buffer.py`）：老师进程自己打局，在选定的决策点分叉游戏，
  在许多个"世界"中评估每个候选动作；这些世界里的隐藏信息（抽牌顺序、未来的随机结果）都是重新抽样的，从不读取真实值。
  最佳候选明显优于网络的选择时，把候选动作和搜索分数写进标签库。学习器对这些候选的 Boltzmann 目标加一个交叉熵项
  （`ppo.exit_coef`、`exit_soft_beta`），按新旧加权，策略认同后不再施加梯度。同种子配对测量下，战斗搜索比 FOOL
  的纯网络高 2.6 个百分点，比静默的纯网络约高 0；战斗外的搜索没有可测的提升，已经关闭。

## 已发布模型的来历

所有训练线都源自同一个从零开始、用 PPO 在 A0 下同时训练全部六个角色（1–4 个座位）的网络，之后用进阶课程分别专精到各个角色。

| 发布 | 角色 | 路径 |
|---|---|---|
| `silent-19m`（v58071） | 静默猎手 | 4M 课程线 → `S25` 4M 在 A10 上纯 PPO（145 亿样本；在另一个封存的 1,000 种子集上 810/1,000 = 81.0%）→ `S34` kickstart 蒸馏到 19M → `S35` PPO + ExIt（19M 网络 45.3 亿样本） |
| `fool-19m`（v40096） | 愚者 | `S31` 4M（153 亿样本）→ `S37` kickstart 蒸馏到 19M → `S38` PPO + ExIt，4 卡学习器（19M 网络 31.3 亿样本） |
| `defect-4m`（v231079） | 故障机器人 | 4M 课程线 → `S39` 在 A10 上 PPO（累计 164 亿样本） |
| `ironclad-4m`（v216143） | 铁甲战士 | 4M 课程线 → `S36` 在 A10 上 PPO + ExIt（累计 152 亿样本） |

## 评测方法

- 报告 EMA 权重在固定种子集上的贪心对局结果，并给出 Wilson 区间。300 局的标准误约 2.3 个百分点，1,000 局约 1.3 个百分点；
  小于这个量级的差异就是噪声。
- 比较两个模型或两种设置时，用同一批种子，并统计"一方赢、另一方输"的局数（`games.jsonl` 每个种子一行）。
- GPU 上的贪心对局不能逐位复现：bf16 下的近似平局会让同一权重的两次运行之间有百分之几的对局翻转。单次读数只能当一个样本。
- 不要在你要报告为"留出集"的种子集上调参。`eval/panels/` 中的 1,000 种子集在训练期间用于监测，本文也是按这个身份报告的。
